2026-03-08: Investigation into exp2 small-resolution failures.
  Root cause: train_insurance_fullimgsize_mamba.py (line 146-147) creates datasets
    with MIMIC_raw(path, resize=args.resize) but does NOT pass upscale_to=448.
    This feeds tiny images (e.g. 2x2, 4x4) directly to MedMamba, which crashes
    because PatchEmbed2D (MedMamba/MedMamba.py, line 209) uses a 4x4 Conv2d kernel
    and PatchMerging2D (lines 236-262) halves spatial dims at each of 3 stages.
  The README documents exp2 as a two-step resize: "Images are resized DOWN to
    the target resolution then UP to 448x448 before feeding to the model."
    bootstrap_evaluate.py (line 486-487) correctly implements this with upscale_to=448.
    But the training script is missing it -- both in our repo AND in Chi-Yu's latest
    push (https://github.com/altis5526/Insurance-Project-Journal-version-.git).
  The original non-MedGemma exp2 weights (exp2/mamba_2.pt through mamba_224.pt) DO
    exist and produce valid bootstrap results for all 8 resolutions. Chi-Yu must have
    trained them with a locally modified script that included upscale_to=448, but that
    version was never committed.
  Fix: add upscale_to=448 to MIMIC_raw() calls in train_insurance_fullimgsize_mamba.py.
  Status: CONFIRMED by Chi-Yu (2026-03-08). He used upscale_to=448 in his original runs.
  Fix applied: added upscale_to=448 to train_insurance_fullimgsize_mamba.py (line 146-148).
